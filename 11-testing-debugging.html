Testing & Debugging

Unit testing with FrappeTestCase, production debugging techniques, and mocking external APIs.

Unit Testing in Frappe
Q01
CORETESTING
How do you write unit tests for Frappe DocTypes? What test utilities does the framework provide?
▾
Answer

Frappe test framework is built on Python unittest. Tests live in myapp/tests/test_*.py and inherit from frappe.tests.utils.FrappeTestCase.

# myapp/tests/test_loan_application.py
import frappe
from frappe.tests.utils import FrappeTestCase

class TestLoanApplication(FrappeTestCase):

    def setUp(self):
        # Create test fixtures
        self.customer = frappe.get_doc({
            "doctype": "Customer",
            "customer_name": "_Test Customer Loan",
            "customer_type": "Individual"
        }).insert(ignore_permissions=True)

    def tearDown(self):
        frappe.db.rollback()  # Frappe auto-rollbacks in tests

    def test_loan_amount_validation(self):
        loan = frappe.get_doc({
            "doctype": "Loan Application",
            "customer": self.customer.name,
            "loan_amount": -1000,  # invalid
        })
        with self.assertRaises(frappe.ValidationError):
            loan.insert()

    def test_approval_changes_status(self):
        loan = make_test_loan(self.customer.name, amount=50000)
        loan.insert()
        frappe.call("myapp.api.approve_loan", name=loan.name)
        loan.reload()
        self.assertEqual(loan.status, "Approved")

Run tests:

bench run-tests --app myapp
bench run-tests --app myapp --module myapp.tests.test_loan_application
bench run-tests --app myapp --doctype "Loan Application"
FrappeTestCase wraps each test in a transaction that's rolled back after — your test DB stays clean without any teardown logic for inserts.
Debugging Production Issues
Q02
SCENARIODEBUG
A production bug is only reproducible with real data — not on staging. How do you debug it safely?
▾
Answer

Safe production debugging techniques:

1. Frappe Error Log: Most exceptions are already captured. Check Error Log DocType first — filter by doctype, user, or time range.

2. Temporary verbose logging: Add frappe.log_error(str(data), "debug label") to the suspected code path. Produces entries in Error Log without affecting users.

# Add temporary debug log (remove after investigation)
def my_function(doc):
    frappe.log_error(
        message=frappe.as_json({
            "doc_name": doc.name,
            "field_value": doc.custom_field,
            "session_user": frappe.session.user,
            "flags": doc.flags
        }),
        title="DEBUG: my_function trace"
    )

3. Replicate with bench console: Connect to production bench console and manually replicate the exact operation with the exact document:

bench --site production.site console
>>> doc = frappe.get_doc("Sales Invoice", "SINV-001234")
>>> doc.validate()  # trigger the validate manually

4. Check request logs: bench logs nginx / bench logs web for raw HTTP errors, 500s, and slow requests.

Never run destructive bench console commands on production. Always bench backup first if you need to test data mutations.
Q03
CORETESTING
How do you mock external API calls (e.g., WhatsApp, payment gateway) in Frappe tests?
▾
Answer

Use Python's built-in unittest.mock — patch the external call at the module level where it's imported:

from unittest.mock import patch, MagicMock
from frappe.tests.utils import FrappeTestCase

class TestWhatsAppNotification(FrappeTestCase):

    @patch("myapp.whatsapp.requests.post")
    def test_notification_sent_on_approval(self, mock_post):
        # Arrange: mock WhatsApp API response
        mock_post.return_value = MagicMock(
            status_code=200,
            json=lambda: {"messages": [{"id": "wamid.test123"}]}
        )

        # Act: approve a loan (should trigger WhatsApp)
        loan = make_test_loan(amount=50000)
        loan.insert()
        frappe.call("myapp.api.approve_loan", name=loan.name)

        # Assert: WhatsApp API was called once with correct payload
        mock_post.assert_called_once()
        call_args = mock_post.call_args
        self.assertIn("50000", str(call_args))

    @patch("myapp.whatsapp.requests.post",
           side_effect=Exception("Network error"))
    def test_approval_succeeds_even_if_whatsapp_fails(self, mock_post):
        # Approval should not fail if notification fails
        loan = make_test_loan(amount=50000)
        loan.insert()
        # Should not raise
        frappe.call("myapp.api.approve_loan", name=loan.name)
        loan.reload()
        self.assertEqual(loan.status, "Approved")
Always test the failure path — your core business logic must succeed even if third-party notifications fail. Wrap notification calls in try/except and log failures.
