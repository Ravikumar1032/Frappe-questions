Hooks & Events

Execution order, override patterns, cross-app hook dependencies, and validate hook debugging.

Execution Order & Overrides
Q01
COREHOOKS
What is the execution order of hooks.py doc_events vs a Controller method override? Which survives a bench update?
▾
Answer

Execution order for before_save:

1. ERPNext Controller class method (e.g., SalesOrder.before_save() in ERPNext source)

2. doc_events hooks from custom apps, in app order from apps.txt

3. Server Script (if any defined in the DB)

Survival after bench update: Controller overrides in your custom app's hooks.py doc_events survive ERPNext updates. Directly patching ERPNext controller files is overwritten on bench update.

Multi-app conflict: Two custom apps hooking the same event — order is determined by apps.txt line order. The last app's hook runs last and can overwrite side effects of the first.

Never edit ERPNext source directly. Always use doc_events in your custom app — it's the only upgrade-safe pattern.
Q02
COREHOOKS
Explain override_whitelisted_methods and override_doctype_class in hooks.py with real use cases.
▾
Answer

override_whitelisted_methods: Replaces a specific @frappe.whitelist() function with your own implementation.

# hooks.py
override_whitelisted_methods = {
    "erpnext.accounts.doctype.payment_entry.payment_entry.get_outstanding_invoices":
        "myapp.overrides.payment.get_outstanding_invoices"
}

Use case: Filter outstanding invoices by branch — the standard method doesn't support custom field filters.

override_doctype_class: Replaces the entire Python controller class for a DocType.

# hooks.py
override_doctype_class = {
    "Sales Invoice": "myapp.overrides.sales_invoice.CustomSalesInvoice"
}
# myapp/overrides/sales_invoice.py
from erpnext.accounts.doctype.sales_invoice.sales_invoice import SalesInvoice

class CustomSalesInvoice(SalesInvoice):
    def on_submit(self):
        super().on_submit()  # run original
        self.send_whatsapp_notification()

Use case: You need to override on_submit to fire a WhatsApp notification immediately as part of the same transaction — doc_events fires too late for your requirement.

Debugging Hooks
Q03
SCENARIODEBUG
A validate hook on Sales Invoice throws exceptions only during bulk import — not in UI. How do you debug and fix it?
▾
Answer

Root cause possibilities:

1. Bulk import via Data Import uses frappe.get_doc().insert() programmatically — frappe.flags may differ. Check if hook reads self.flags.ignore_validate inconsistently.

2. frappe.session.user is often Administrator in bulk import — if hook does user-specific logic, it may fail.

3. Fields not in CSV (e.g., amended_from, child table rows) are None during import. Missing null guards cause AttributeError.

Debug steps:

# In your validate hook, log the traceback:
def validate(self):
    try:
        your_custom_logic(self)
    except Exception:
        frappe.log_error(frappe.get_traceback(),
                         "SI Validate Debug")
        raise  # re-raise so import marks row as failed

Then trigger via bulk import → check Error Log DocType in UI.

Fix pattern: Guard all field reads against None:

# WRONG
if self.custom_field.startswith("X"):  # AttributeError if None

# CORRECT
if getattr(self, 'custom_field', None) and \
   self.custom_field.startswith("X"):
Use frappe.get_doc().insert(ignore_mandatory=True) in test scripts to replicate import behavior exactly.
Q04
SCENARIOHOOKS
Two custom apps both define a before_save hook on Sales Order. App B's hook depends on data set by App A's hook. How do you guarantee order?
▾
Answer

Order is controlled by apps.txt — apps listed later run their hooks later. So if App A is listed before App B in apps.txt, App A's hook always runs first.

Verification: Check bench/sites/apps.txt — it lists installed apps in order. Rearrange by reinstalling with correct order or editing directly.

Fragile pattern — avoid: Never have cross-app hook dependencies if possible. The order is not explicitly declared in code — it's an operational fact of the bench installation.

Robust alternative: Make App B's hook self-contained. If it depends on App A having set a field, read the field defensively and compute it inline if absent:

def my_app_b_hook(doc, method):
    # Don't assume App A ran first
    territory = doc.get("custom_territory") or \
                derive_territory_from_address(doc)
    doc.custom_zone = map_territory_to_zone(territory)
