Integrations & APIs

Mobile REST API design, credential management, third-party sync patterns, and retry strategies.

REST API Design
Q01
COREAPI
How do you design a mobile-app-ready REST API layer on top of ERPNext? What are the key concerns?
▾
Answer

Architecture decisions:

1. Auth: Use Frappe's API key + secret token auth — Authorization: token api_key:api_secret. One key per mobile user. Never use session cookies from mobile apps.

2. Purpose-built endpoints: Don't expose raw frappe.get_list() — build thin whitelisted methods returning only needed fields:

@frappe.whitelist()
def get_my_dashboard():
    """Mobile dashboard — returns minimal payload"""
    user = frappe.session.user
    return {
        "pending_orders": frappe.db.count("Sales Order", {
            "owner": user, "status": "Draft"
        }),
        "today_collections": get_today_collection(user),
        "unread_notifications": frappe.db.count("Notification Log", {
            "for_user": user, "read": 0
        })
    }

3. Pagination: All list endpoints must support limit + start or cursor-based pagination. Never return unbounded lists to mobile.

4. Versioning: Prefix all custom endpoints: myapp.api.v1.get_dashboard — makes breaking-change management tractable across mobile app versions.

5. Rate limiting: Add Nginx rate limiting per API key. Frappe has no built-in rate limiting.

# nginx.conf — rate limit by API key header
limit_req_zone $http_authorization zone=api_limit:10m rate=30r/m;

location /api/ {
    limit_req zone=api_limit burst=10 nodelay;
    proxy_pass http://frappe_app;
}
Third-Party Integrations
Q02
COREINTEGRATION
How do you store and rotate third-party API credentials (keys, secrets, tokens) securely in Frappe?
▾
Answer

Options (ranked by security:)

1. site_config.json — stored on disk outside the DB. Not editable by UI users. Best for infrastructure credentials:

# site_config.json
{
  "payment_gateway_secret": "sk_live_xxxx",
  "whatsapp_token": "EAAxxxxxxx"
}

# Access in code:
secret = frappe.conf.payment_gateway_secret

2. Custom Single DocType with password fields — editable via UI by admins. Fields of type Password are stored encrypted in DB:

# DocType: Integration Settings (issingle: 1)
# Field: api_key (fieldtype: Password)

# Reading:
settings = frappe.get_single("Integration Settings")
key = settings.get_password("api_key")  # decrypts automatically

3. Environment variables — best for containerized/cloud deployments. Access via os.environ.get()

Rotation strategy: Store current + previous credential. During rotation window, try current first, fall back to previous. Eliminates downtime during key rotation.

Never hardcode credentials in Python files or commit them to git. Use frappe.conf or encrypted Password fields always.
Q03
SCENARIOINTEGRATION
You need to sync ERPNext Customer data to a CRM in real-time. The CRM API is slow (avg 2s). How do you design this?
▾
Answer

Wrong approach: Calling CRM API directly inside after_insert / on_update hooks — this blocks the web request for 2 seconds and fails if CRM is down.

Correct approach — async event-driven sync:

# hooks.py
doc_events = {
    "Customer": {
        "after_insert": "myapp.crm_sync.queue_sync",
        "on_update": "myapp.crm_sync.queue_sync"
    }
}

# myapp/crm_sync.py
def queue_sync(doc, method):
    """Called in web request — must return fast"""
    frappe.enqueue(
        "myapp.crm_sync.push_to_crm",
        customer_name=doc.name,
        queue="default",
        timeout=60,
        # Deduplicate: don't queue if already queued
        job_name=f"crm_sync_{doc.name}"
    )

def push_to_crm(customer_name):
    """Runs in background worker — can be slow"""
    customer = frappe.get_doc("Customer", customer_name)
    payload = build_crm_payload(customer)
    
    for attempt in range(3):  # retry up to 3 times
        try:
            response = call_crm_api(payload)
            if response.status_code == 200:
                customer.db_set("crm_synced", 1)
                return
        except Exception:
            if attempt == 2:
                frappe.log_error(frappe.get_traceback(),
                                  f"CRM sync failed: {customer_name}")
            time.sleep(2 ** attempt)  # exponential backoff
Use job_name parameter in frappe.enqueue() for deduplication — if the same customer is updated 5 times quickly, only one sync job runs.
