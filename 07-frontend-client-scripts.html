Frontend & Client Scripts

Form lifecycle hooks, race condition prevention, Promise chaining, and client script best practices.

Form Lifecycle Events
Q01
COREFRONTEND
What is the difference between setup, refresh, and onload in a Frappe client script? When does each fire?
▾
Answer

onload: Fires once when the form first loads into the browser. Good for one-time setup based on URL params or route context. Does NOT re-fire on save or when navigating back to same doc.

setup: Fires once after the form controller class is instantiated. Good for binding set_query filters, formatters, and event listeners. Also fires only once per form lifetime in the browser tab.

refresh: Fires every time the form is rendered or re-rendered — initial load, after save, after submit, after route change back. Most commonly used hook. Use for conditional UI: show/hide fields, add custom buttons based on doc state.

frappe.ui.form.on("Sales Order", {
    setup(frm) {
        // Once: configure Link field query
        frm.set_query("territory", () => ({
            filters: { is_group: 0, disabled: 0 }
        }));
    },

    onload(frm) {
        // Once: read URL param
        const src = frappe.utils.get_url_arg("source");
        if (src) frm.set_value("lead_source", src);
    },

    refresh(frm) {
        // Every render: conditional button
        frm.remove_custom_button("Approve");
        if (frm.doc.docstatus === 0 &&
            frm.doc.status === "Pending Approval") {
            frm.add_custom_button("Approve",
                () => approve_order(frm));
        }
    }
});
Always remove_custom_button before add_custom_button inside refresh — otherwise buttons accumulate on each render.
Race Conditions & Async
Q02
SCENARIOFRONTEND
A frappe.call() in a client script causes double-submission when users rapidly click Approve. How do you prevent it at both client and server level?
▾
Answer

Client-side prevention:

let submitting = false;

frappe.ui.form.on("Loan Application", {
    refresh(frm) {
        frm.add_custom_button("Approve", function() {
            if (submitting) return;  // guard
            submitting = true;

            frappe.call({
                method: "myapp.api.approve_loan",
                args: { name: frm.doc.name },
                freeze: true,          // disables the whole form
                freeze_message: "Approving...",
                callback(r) {
                    submitting = false;
                    frm.reload_doc();
                },
                error() {
                    submitting = false;
                }
            });
        });
    }
});

Server-side guard (mandatory — client guard is UX only):

@frappe.whitelist()
def approve_loan(name):
    doc = frappe.get_doc("Loan Application", name)
    # Optimistic lock: check status before mutating
    if doc.status != "Pending Approval":
        frappe.throw(
            f"Already processed (status: {doc.status})",
            frappe.ValidationError
        )
    doc.db_set("status", "Approved")
    frappe.db.commit()
frappe.call() with freeze:true is the fastest UX fix. But server-side status check is the only security guarantee.
Q03
COREFRONTEND
How do you make a frappe.call() chain without callback hell? Show the Promise-based pattern.
▾
Answer

Frappe's frappe.call() returns a jQuery Deferred — you can use .then() chaining:

// Promise chain
frappe.call({
    method: "myapp.api.get_customer_details",
    args: { customer: frm.doc.customer }
}).then(r => {
    const details = r.message;
    frm.set_value("credit_limit", details.credit_limit);

    // Chained call
    return frappe.call({
        method: "myapp.api.check_outstanding",
        args: { customer: frm.doc.customer }
    });
}).then(r => {
    if (r.message.outstanding > frm.doc.grand_total) {
        frappe.show_alert({
            message: "Customer has outstanding dues",
            indicator: "orange"
        });
    }
}).catch(err => {
    frappe.msgprint("Failed to load customer details");
    console.error(err);
});
For parallel calls, use Promise.all with frappe.call() — much faster than sequential chains when calls are independent.
